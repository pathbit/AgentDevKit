# Regras

Orientam contextos recorrentes. Use `criar-regra` quando uma convenção precisar
valer em várias tarefas; salve em `<nome>/RULE.md` e defina seu escopo.

- [Estrutura](estrutura/RULE.md): organização, concisão e sincronização.
- [Qualidade](qualidade/RULE.md): testes, evidências e Markdown.
- [Git](git/RULE.md): commits, autoria e publicação.
- [Ambiente local](ambiente-local/RULE.md): estrutura, Docker e comandos reais.
- [Documentação](documentacao/RULE.md): revisão após toda implementação.
- [Próximos passos](proximos-passos/RULE.md): continuidade explícita por etapa.
- [Segurança](seguranca/RULE.md): acesso, dados, entradas e triagem de riscos.
- [Execução local](execucao-local/RULE.md): análise local sem expor fontes ou segredos.

O Cursor usa regras `.mdc`; se o espelho não for carregado automaticamente,
peça leitura explícita. Preserve o escopo nos formatos nativos disponíveis.
Uma regra vale transversalmente; não é um roteiro completo de execução.
As novas regras são `always_on`, com ações condicionadas à tarefa descrita.
