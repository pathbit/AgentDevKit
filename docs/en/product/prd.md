# PRD AgentDevKit

[Português (Brasil)][reading-pt] · [English][reading-en] · [Español][reading-es]

## Problem and public

Developers need to reuse agent instructions between projects and customers
without copying divergent procedures, losing local settings or starting code
before setting the product.

AgentDevKit serves people and teams who use development agents in new or
existing projects. The first delivery distributes the kit already extracted from
the original project as an independent product.

Repeated executions must be idempotent; CLI offers simulation and JSON. The
instructions remain concise, with optional details in references. In the
interactive configuration, the user chooses his agents. In automations, the
explicit option or saved choice guide the installer. PRD, the absence of choice
selected all customers by compatibility. [installation guide][install] document
current patterns and migration.

## Limits and success

Kit does not set project stack, does not publish automatically, does not create
PRD/specs Undiscovered and does not prove loading by the client just by
generating files. Do not copy actual product documents for the target project.

Delivery requires empty and existing design tests, file preservation, update,
languages, catalogs and distribution without local artifacts. [initial
spec](../specs/v0.0.1/SPEC.md); a [selection spec](../specs/v0.0.2/SPEC.md)
details the installation by agent. [spec v0.0.6](../specs/v0.0.6/SPEC.md) it
deals with the public presentation, the distributed license and the verified
update of the origin project.
