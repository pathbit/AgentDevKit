# Delivery Review

[Português (Brasil)][reading-pt] · [English][reading-en] · [Español][reading-es]

The real report is one JSON ed
`.agent-tests/<referencia>/<execucao>/revisao.json`, without another copy
Markdown. Generate it by script `revisar-entrega prepare --id <referencia>`,
`--spec` or `--scope` as the change. Preserve the snapshot generated by the
script.

| Field | Contract |
| --- | --- |
| `version` | `1`. |
| `reference`, `execution` | Change and execution identifiers. |
| `spec` | Path of the spec or `null` for change without spec. |
| `snapshot` | Mode, HEAD, hashes, spec and revised mandatory documents. |
| `baseline` | Path and hash of the original scope generated by `prepare`. |
| `documentation` | Path, decision and justification by document. |
| `validation` | Criterion AC-001, method, prerequisite, assertion and evidence. |
| `review` | Reviewer, status and findings of the final state. |

Documentation decisions: `pending`, `updated`, `no-impact`, `not-applicable`.
Validation status: `pending`, `passed`, `failed`, `not-run`, `not-applicable`.
Every absence of impacto/aplicação need justification. Evidence must exist in
relative paths under the ignored execution folder; test code remains versioned.
Without spec, set own criteria with AC-001 IDs; `spec: null` does not waive the
prerequisites for implementing features. Gate only approves criteria with
`passed` and evidence. A non-applicable acceptance requires reviewing the
approved scope; marking `not-applicable` Don't let him go.

The reviewer works in reading; the main agent records his findings in JSON.
`review.status` It just goes from `pending` a `approved` after closing findings
`open` how `resolved` and review the final state. Subsequent changes require new
snapshot, affected checks and new revision. Delegation error or no response
keeps the review pending. The seal checks the registered data; it does not prove
that the review happened.

Run `revisar-entrega seal <relatorio>` after independent approval and
`revisar-entrega check <relatorio>` prior to commit/merge. `baseline.json` e
`seal.json` the script confers consistency, coverage, files and evidence; the
human review or reviewer review assesses the semantics and the quality of the
result.
