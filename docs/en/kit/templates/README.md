# Templates

[Português (Brasil)][reading-pt] · [English][reading-en] · [Español][reading-es]

Order: preparation → PRD → UX/UI → design → roadmap → approved spec and plan →
technical configuration → implementation and review → release. Use the
corresponding skills to gather answers and fill the templates. Files in this
folder are bases, not approved documents. Do not create `docs/` while the user
is preparing only the structure of the agents.

| Template | Start on | Evolve when |
| --- | --- | --- |
| [README root][readme] | Preparation | Phase, use or ability to change. |
| [README folder][pasta] | Synchronising folder | Entrances or purpose change. |
| [AGENTS][agentes], [CLAUDE][claude] when selected | Preparation | Structure or client change. |
| [Root entries][entrypoints] | Installation | Client change. |
| [Settings][config] | Preparation | Product and stack are set. |
| [Root Files][raiz] | Settings | Contracts change. |
| [Gitignore][ignore] | Preparation | Ignored artifacts change. |
| [PRD][prd] | Product | Scope or criteria for success change. |
| [UX/UI][ux], [design][design] | After PRDon the agenda | Journeys or architecture change. |
| [Roadmap][roadmap] | After Design | Increases or priorities change. |
| [ADR][adr] | Design | Structural decision aceita/substituída. |
| [Local environment][ambiente] | Settings | Stack or setup change. |
| [Legacy lifting][levantamento] | Document system in use | New evidence or doubts arise. |
| [Contribution][contrib] | Settings | Development flow change. |
| [Spec][spec], [plan][plano] | Delivery Planning | Scope, criteria or execution change. |
| [Tasks][tasks] | Implementation approved | Execution or evidence change. |
| [Delivery Review][revisao] | Implementation | Before commit/merge. |
| [Release][release], [CHANGELOG][changelog] | First delivery | Publish. |
| [SECURITY][security] | Public support | Política/suporte change. |
| [Safety review][security-review] | Authorised analysis | Threats and evidence. |
| [Command][comando] | Agentic resource | Input or flow change. |

Instead, make up and read existing documents with `atualizar-documentacao`. Use
templates as a list of gaps. Copy only applicable artifacts that are still
missing; never replace existing documents. Remove placeholders and confirm facts
in new files; preserve names, formats, sections and previous decisions. README
follows the project since preparation; product documents appear after discovery.
Security depends on really defined support and channel.

Spec criteria use AC-001 IDs. The test code is versioned; results are in
`.agent-tests/<referencia>/<execucao>/`. The only review report is JSON
generated by the script; the model explains the contract, without duplicating it
in MD. Baseline and seal are metadata generated to detect later changes. Models,
settings and reports are not mirrored in agents folders.
