# Rules

[Português (Brasil)][reading-pt] · [English][reading-en] · [Español][reading-es]

They guide recurring contexts. `criar-regra` when a convention needs to be valid
for multiple tasks; save to `<nome>/RULE.md` And set your scope.

- [Structure](estrutura/RULE.md): organization, concision and synchronization.
- [Quality](qualidade/RULE.md): tests, evidence and Markdown.
- [Git](git/RULE.md): commits, authorship and publication.
- [Local environment](ambiente-local/RULE.md): structure, Docker and real
  commands.
- [Documentation](documentacao/RULE.md): review after all implementation.
- [Next steps](proximos-passos/RULE.md): explicit continuity per step.
- [Security](seguranca/RULE.md): access, data, input and risk sorting.
- [Local execution](execucao-local/RULE.md): local analysis without exposing
  sources or secrets.

Choose the activation of the rule by scope and preserve that scope in native
formats. [compatibility](../COMPATIBILIDADE.md) the client and ask for explicit
reading if the format available requires. A rule guides a recurring context. Use
commands and skills to conduct the task.
