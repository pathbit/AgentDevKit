# Create UX/UI

[Português (Brasil)][reading-pt] · [English][reading-en] · [Español][reading-es]

Check out the preparation and its evidence in
`.pbai4devs/state/configuracao/ESTADO.md` e o PRD approved with evidence. If
there are gaps, forward the first to `configurar-projeto` or `criar-prd` before
writing. Reuse existing documents with `atualizar-documentacao`.

Gather questions about users, journeys, interfaces, accessibility, platforms,
states, references and how to validate the experience. `documentos.ux_ui` for
[template](../../../templates/ux-ui/TEMPLATE.md) and link the PRD. If the
interface appears out of scope, confirm with the user and register the reason.
Distinguish what exists in the project of the model content.

New or modified document materially stays in `status: rascunho`. Solve essential
decisions, obtain explicit approval and record the evidence with `status:
aprovado` or `status: nao-aplicavel`, according to the decision. Preserve valid
approvals. Evaluate design and dependent specs and reopen only with proven
material impact and authorization. Register pending in doubt. Update roadmap,
README and documents affected according to impact.

After approval, forward the pending step with `proximos-passos`. Follow the
quality rule. Synchronize only if agent resources change.
