# Create PRD

[Português (Brasil)][reading-pt] · [English][reading-en] · [Español][reading-es]

Check out the preparation and its evidence in
`.pbai4devs/state/configuracao/ESTADO.md`. If it is not proven, forward the
`configurar-projeto` before writing or asking about the product. The technical
configuration may stay pending. Use saved customers and language, unless you
choose the order. Check the files before reporting gaps.

Use `atualizar-documentacao` and reuse what exists. Gather questions about
problem, public, objectives, scope, requirements, restrictions, priorities and
success criteria. Use facts, user decisions and explicit assumptions. Create the
document when the product starts. Fill gaps in `documentos.prd` for [model of
PRD](../../../templates/prd/TEMPLATE.md).

PRD new or changed materially stays in `status: rascunho`. Solve the essential
decisions, confirm the person responsible if there is doubt, obtain explicit
approval and record the evidence with `status: aprovado`. Preserve valid
approvals. Reevaluate UX/UI, design and specs and reopen only with proven
material impact and authorization. Register pending when impact is uncertain.
Update README and roadmap when affected.

With PRD approved, use `proximos-passos` to forward the UX/UI or identify the
next step if the experience is already approved or dispensed with approved
justification. Follow the quality rule. Synchronize only if agents' resources
change.
