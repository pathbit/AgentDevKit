# Integration of preservation TOML

This map complements the [spec](SPEC.md). A local candidate integrates the
editing to the installer and sync; it still needs to meet the acceptance
criteria and does not represent a published release.

The candidate maintains the current format of `blocks`: the digest of the new
format TOML link version, block and source comment; in the legacy remains the
hash of the block. The comment records only data required for editing and does
not copy the human text. The steps below remain requirements in evaluation. In
fixtures, complete cycles and state transitions preserved Git and the TOML
observed; divergent staged file was refused. A downgrade proof with the CLI
`0.0.21` it was also refused to preserve the observed files; this does not
guarantee the behavior of other older versions or situations. On Linux, nine
fixtures passed through `init`, `update`, direct sync and removal, restoring the
TOML and preserving the observed Git files. The proof used LF, files TOML
untraceable and the kit parser; does not cover Windows or the real Gemini. In
macOS, a prototype has also passed 40 cases with independent parser. CLI 0.67.0
accepted V3 commands in the four forms generated by the helper and expanded a
synthetic reference and argument. An independent parser also accepted the files;
the proof used configuration
simulated, without network, model or complete installation flow. TOML staged and
unstaged edition divergent, fixtures in macOS and Linux observed refusals in
`init`, `update` and in both sync paths; customer exchange preserved the index
and restored the human text. Windows, ACLs, extended attributes or all stable
combinations were not tested.

## Status and planning

1. Set log versioned by Gemini path, with block and comment digest and minimum
   data on separators and delimiters. Validate paths, limits and relationship
   with `blocks`; do not register human text.
2. In `loadState`, `reconcileStateBytes`, `readDerivedState` e `derivedContent`,
   validate and preserve the unknown record and fields. Reconciliate the
   installed state, the derivative and its removals without silent precedence
   when there is conflict.
3. Transport the validated record to the private stage and to the `init`,
   `update` and direct sync. A pre-existing origin without proven property
   should not be adopted. Missing, divergent or orphaned data should preserve
   the file and produce diagnosis before public alteration.
4. In the exchange of clients, removal of resources and consolidation of the
   state, withdraw only the registration associated with the proven operation.
   `doctor` e `sync --check` they must inform partial or divergent states.
5. Recheck status and approved bytes before application. TOML and state are not
   published atomically, an interruption may leave the pair incomplete: diagnose
   and preserve without promising automatic recovery. Rollback and competition
   follow their own spec.
6. Migrate the record between state paths only with proven transition. Ancient
   versions can ignore it or reserialize it TOML; test real downgrade and do not
   assume that an old binary respects the new policy.

Digest records consistency; it does not authenticate the authorship or identity
of the file and does not prove permissions or metadata of the file system.

## Evidence required

- Add, update and remove in all four forms TOML and without prompt, with
  independent parser, BOM, LF/CRLF and human editions before and after the
  block.
- Verify missing, changed, duplicated or out of position comments; similar text
  within a string is not metadata comment.
- Exercise CLI and sync direct in both orders, with stable indexes and unstaged
  changes, including customer exchange, legacy, migration and partial status.
  Compare human files, index, Git configuration, ignores and res.
- Test the package installed without `node_modules` the project, with parser and
  distributed license, and test old and current versions in disposable fixtures.
- Check `{{args}}` in the prompt and inclusions: an occurrence in the TOML The
  policy of this case remains pending.

Do not consider these points approved based only on a helper or memory test;
public flows and their limitations need evidence.
