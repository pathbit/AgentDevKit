# Guided terminal experience

[Português (Brasil)][reading-pt] · [English][reading-en] · [Español][reading-es]

When adopting the kit, the team needs to know what to check and what resource to
use next. In an existing project, it also needs to take advantage of the
documents that already guide the work.

## Acceptance criteria

- **AC-001** A CLI chain installation, diagnosis, synchronization verification
  and orientation. Divergences allow you to review the plan before applying. The
  intention to execute an application keeps the focus on the environment.
- **AC-002** Optional integration query works before and after installation.
  Displays recognized paths and guides their use without reading the contents of
  artifacts, following symbolic links, or running them.
- **AC-003** O README distributed by npm and the guide at GitHub describe when
  adopting the kit, how to start and when to consult BMad, OpenSpec, GitHub Spec
  Kit, Tech Leads Club or Dotcontext.
- **AC-004** The package goes through the compatibility and update matrices.
  Validation in a Talquee copy compares own files and Git index.
