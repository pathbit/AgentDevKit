# Crear diseño técnico

[Português (Brasil)][reading-pt] · [English][reading-en] · [Español][reading-es]

Revise la preparación y sus evidencias en
`.pbai4devs/state/configuracao/ESTADO.md`, o PRD aprobado y UX/UI aprobado o no
aplicable con justificación aprobada. Si hay lagunas, encaminé la primera con
`proximos-passos` Antes de escribir. Use `atualizar-documentacao` Para
reaprovechar lo que existe.

Reúna dudas sobre arquitectura, tecnología, componentes, integraciones, datos,
requisitos no funcionales, seguridad, pruebas, implantación, opciones y riesgos.
Use `usar-skills-externas` para referencias pertinentes. Regístra decisiones y
pendencias en `documentos.design` el
[modelo](../../../templates/design/TEMPLATE.md), con vínculos al PRD e UX/UI. La
instalación de estack se encuentra para la configuración técnica.

Documento nuevo o modificado materialmente se encuentra en `status: rascunho`.
Resolva decisiones esenciales y registre `status: aprovado` con evidencia sólo
después de la aprobación explícita. Preserve aprobaciones válidas. Avalie specs
afectadas y reabra sólo con impacto material comprobado y autorización. Regístra
espera en la duda. Actualizar README, roadmap y ADRs pertinentes.

Después de la aprobación, use `proximos-passos` Para encaminar la planificación
de los incrementos antes de las specs. Siga la regla de calidad. Sincronize
solamente si recursos de los agentes cambian.
