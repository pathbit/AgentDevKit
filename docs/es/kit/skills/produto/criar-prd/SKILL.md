# Crear PRD

[Português (Brasil)][reading-pt] · [English][reading-en] · [Español][reading-es]

Revise la preparación y sus evidencias en
`.pbai4devs/state/configuracao/ESTADO.md`. Si no está comprobada, encaminé a
`configurar-projeto` Antes de escribir o preguntar sobre el producto. La
configuración técnica puede estar pendiente. Use clientes y idioma guardados,
salvo que elija la petición. Consulte los archivos antes de informar sobre las
lagunas.

Use `atualizar-documentacao` y reaproveche lo que existe. Reúna dudas sobre
problema, público, objetivos, alcance, requisitos, restricciones, prioridades y
criterios de éxito. Use hechos, decisiones del usuario y supuestos explícitos.
Cree el documento cuando el producto comience. Rellene lagunas en
`documentos.prd` el [modelo de PRD](../../../templates/prd/TEMPLATE.md).

PRD nuevo o modificado materialmente está en `status: rascunho`. Resolva las
decisiones esenciales, confirme el responsable si hay duda, obtenga aprobación
explícita y registre la evidencia con `status: aprovado`. Preserve aprobaciones
válidas. Reavalie UX/UI, diseño y specs y reabra sólo con impacto material
comprobado y autorización. Regístra espera cuando el impacto sea incierto.
Actualizar README y roadmap cuando se ven afectados.

Com PRD aprobado, use `proximos-passos` para encaminar a UX/UI o identificar la
etapa siguiente si la experiencia ya está aprobada o dispensada con
justificación aprobada. Siga la regla de calidad. Sincronize solamente si
recursos de los agentes cambian.
