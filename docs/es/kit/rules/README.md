# Reglas

[Português (Brasil)][reading-pt] · [English][reading-en] · [Español][reading-es]

Orientan contextos recurrentes. Use `criar-regra` cuando una convención necesite
valer en varias tareas; salve en `<nome>/RULE.md` y defina su alcance.

- [Estructura](estrutura/RULE.md): organización, concisión y sincronización.
- [Calidad](qualidade/RULE.md): pruebas, evidencias y Markdown.
- [Git](git/RULE.md): commits, autoría y publicación.
- [Ambiente local](ambiente-local/RULE.md): estructura, Docker y órdenes reales.
- [Documentación](documentacao/RULE.md): revisión después de toda
  implementación.
- [Siguientes pasos](proximos-passos/RULE.md): continuidad explícita por etapa.
- [Seguridad](seguranca/RULE.md): acceso, datos, entradas y selección de
  riesgos.
- [Ejecución local](execucao-local/RULE.md): análisis local sin exponer fuentes
  o secretos.

Elija la activación de la regla por el alcance y preserve este alcance en los
formatos nativos. Consulte [compatibilidad](../COMPATIBILIDADE.md) del cliente y
la pieza lectura explícita si el formato disponible requiere. Una regla orienta
un contexto recurrente. Use órdenes y skills para conducir la tarea.
